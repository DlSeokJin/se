## 1. 서론

### 1.1 목적 및 범위
이 문서는 조직 내 협업 활성화를 위해 사용자가 웹 브라우저를 통해 파일을 저장, 공유, 버전 관리할 수 있는 '미니 드라이브' 프로젝트의 요구사항을 조사하고 정의하는 문서이다. 이 문서는 기능적, 비기능적, 인터페이스에 요구되는 사항들을 구조적/동적 관점에서 분석한다.

### 1.2 용어 정의
| 용어 | 설명 |
| :--- | :--- |
| **JWT (JSON Web Token)** | 사용자 인증을 위해 서버가 클라이언트에게 발급하는 암호화된 토큰 |
| **계층형 폴더** | 트리 구조 형태로 폴더 안에 하위 폴더를 생성하여 관리할 수 있는 구조 |
| **버전 복구** | 파일이 수정 또는 삭제되었을 때, 이전 상태의 파일로 되돌리는 기능 |

#### 2.2.2 UseCase Description (유스케이스 상세 설명)

**[UC_03] 파일을 업로드한다**
* **Primary Actor (주 액터):** 사용자
* **Importance Level (중요도):** High
* **Brief Description (개요):** 사용자가 로컬 기기의 파일을 클라우드 서버로 업로드하는 기능을 표현한다.
* **Normal Flow (정상 흐름):**
  1. 사용자가 업로드 버튼을 누르고 파일을 선택한다.
  2. 시스템은 파일 메타데이터(크기, 확장자)를 읽는다.
  3. 시스템은 파일을 암호화하여 스토리지에 저장한다.
  4. 시스템은 업로드 완료 메시지를 화면에 출력한다.
* **Exceptional Flows (예외 흐름):**
  * 2.a1: 파일 용량이 제한을 초과할 경우, 시스템은 업로드 실패 메시지를 출력하고 프로세스를 중단한다.

### 3.2 CRC 카드

**[C_01] 클래스명: 파일 (File)**
* **Type:** Concrete, Domain
* **Associated Use Case:** UC_03, UC_06, UC_07
* **Description:** 시스템에 저장되는 파일 객체를 나타낸다.
* **Responsibilities (책임) 및 Collaborators (협력자):**
  * 파일 업로드 및 다운로드 처리 (협력자: 사용자, 스토리지 DB)
  * 파일 메타데이터 제공 (협력자: 메타데이터 DB)
* **Attributes (속성):** 파일 ID, 파일명, 파일 크기, 업로드 날짜
* **Relationships (관계):**
  * Aggregation (has-parts): 폴더 (Folder)
  * Other Associations: 공유 링크 (ShareLink)

**[C_02] 클래스명: 공유 링크 (ShareLink)**
* **Type:** Concrete, Domain
* **Associated Use Case:** UC_05
* **Description:** 외부 사용자에게 파일을 공유하기 위한 링크 객체이다.
* **Responsibilities (책임) 및 Collaborators (협력자):**
  * 고유 링크 URL 생성 (협력자: 파일)
  * 링크 유효기간 및 접근 권한 검증 (협력자: 사용자, 시스템)
* **Attributes (속성):** 링크 URL, 만료 일자, 권한 타입 (읽기/쓰기)
* **Relationships (관계):**
  * Other Associations: 파일 (File)

## 4. 인터페이스 분석

- 사용자 인터페이스 (UI): 웹 브라우저(Chrome, Edge, Safari 등) 기반의 반응형 웹 인터페이스를 제공한다.

- 소프트웨어 인터페이스: 알림 전송을 위해 사내 이메일 시스템(SMTP API)과 연동한다.

## 5. 제약사항

- 파일 검색 결과는 어떠한 상황에서도 2초 이내에 출력되어야 한다. (성능 제약)

- 모든 파일은 스토리지에 저장되기 전 반드시 AES-256 규격으로 암호화되어야 한다. (보안 제약)

프로젝트 정의서에서 제시한 핵심 기능 분석을 기반으로 대상 시스템에서 중요하게 고려해야 할 품질 요소 추정 및 정리하기

(1) 사용자가 원하는 기대치는?

"사용자는 업무의 연속성과 효율성을 최우선으로 생각함"

가용성: 약 200명의 직원이 업무 시간의 99% 이상 시스템을 이용하는데 불편함이 없어야 함을 보장해야 함.

성능 효율성: 파일 검색 결과가 2초 이내에 표시되어야 하며, 동시 접속자가 많더라도 위 시간을 보장해야 함.

사용성: 웹 브라우저만으로 간단히 파일을 업로드 및 다운로드 할 수 있어야 함

신뢰도: 실수로 삭제된 파일도 30일 내에 안전하게 복구할 수 있어야 함 (데이터 무결성)



(2) 개발자 혹은 유지보수 담당자가 원하는 기대치는?

보안: 데이터 접근 및 전송 시 암호화를 통해 데이터 유출을 방지해야 함. 예컨데 로그인 시 사용자 인증이 완료되면 JWT 토큰을 발급하여 허용된 범위만큼만 접근을 허용할 수 있음.

유지보수: 향후 문서 공동편집이나 AI 검색 기능이 추가될 것을 고려하여 표준 코딩 규약을 준수하며 정형화 되어있어야 함

확장성: 사용자 수나 데이터 저장량이 증가할 때 서버를 유연하게 확장할 수 있는 아키텍처 구조가 설계되어야 함.


(3) 개발 조직의 관리자가 원하는 기대치는?

운영 효율성: 200명 규모의 사용자 계정을 생성, 삭제하고 사용자의 저장공간을 효율적으로 통제할 수 있어야 함

보안 및 규정 준수: 외부 협력 업체와 파일 공유 시, 링크 만료 기간 설정 정책을 강제하여 조직 내부 자료의 외부 유출 방지 및 보안 사고 리스크를 관리해야 함.

비용 및 자원 최적화: 시스템 사용량 모니터링을 통해 불필요한 저장 공간 낭비를 줄이고, 인프라 운영 비용을 최적화할 수 있어야 함.
